Models & Messages Quick Reference

Chapter 4 essentials: provider-neutral model initialization, the message protocol, structured output, and what every model can and can't do. Keep this open as you work through the course.

Provider-Neutral Model Initialization

LangChain's init_chat_model lets you write provider-agnostic code. Swap the provider:model_id string to change the backend without changing your logic.

from langchain.chat_models import init_chat_model

# OpenAI
model = init_chat_model("openai:gpt-5.5", temperature=0)

# Anthropic
model = init_chat_model("anthropic:claude-sonnet-4-6", temperature=0)

# Ollama (local)
model = init_chat_model("ollama:llama3.1", temperature=0)
Install the provider package

Each provider requires a separate pip package: langchain-openai, langchain-anthropic, langchain-ollama. The core langchain package dispatches to the correct provider based on the prefix.

Official: docs.langchain.com/oss/python/langchain/models · reference.langchain.com (init_chat_model) · providers-and-models

These parameters are accepted by init_chat_model and most model constructors. Support and semantics vary by provider (see caveats below).

Message Types

Every turn in the agent loop is represented by a typed message object. These live in langchain.messages and are the same classes used behind the scenes in create_agent.

ClassRole in the LoopKey Fields
SystemMessage Sets the model's behavior and constraints at the start of the conversation. .content holds the system prompt text.
HumanMessage User input. Starts the loop in agent.invoke({"messages": [...]}). .content holds the user input text.
AIMessage Model response. Carries the final answer or tool_calls that continue the loop. .content holds the text answer. .tool_calls is a list of ToolCall dicts (name, args, id). .usage_metadata provides standardised token-usage info (input_tokens, output_tokens, total_tokens) when available. .response_metadata holds provider-specific response metadata (finish reason, etc.).
ToolMessage Result of a tool execution. Fed back into the loop for the model's next decision. .content holds the tool output. .tool_call_id correlates to the AIMessage.tool_calls[i].id that requested it.
AIMessageChunk Partial token chunk produced by model.stream(). Accumulated by the loop into a complete AIMessage. .content holds a token text fragment.

Tool call correlation: When the model requests a tool via AIMessage.tool_calls, each call carries a unique id. The tool's return value is wrapped in a ToolMessage whose tool_call_id matches that id, so the model knows which result belongs to which request.

Official: docs.langchain.com/oss/python/langchain/messages

System prompt is implicit

create_agent(system_prompt=...) prepends a SystemMessage at the head of every turn. You never construct one manually, but you can, and it's the same object the harness creates for you.

System Prompt Pattern

A system prompt is a SystemMessage placed at the start of the conversation. It shapes the model's behavior:

from langchain.messages import SystemMessage

system = SystemMessage(
    content="You are a helpful assistant. "
            "You have access to tools for looking up order status. "
            "Always be concise and accurate."
)

# Or pass as string to create_agent:
agent = create_agent(
    model="openai:gpt-5.5",
    tools=[my_tool],
    system_prompt="You are a helpful assistant. ...",
)

Under the hood, create_agent wraps your string in a SystemMessage and prepends it to the message list on every invocation.

Structured Output

Method 1: with_structured_output (model level)

Bind a Pydantic schema directly to a chat model. The model returns parsed, validated structured data instead of free text.

from pydantic import BaseModel
from typing import Literal

class OrderStatus(BaseModel):
    order_id: str
    status: Literal["shipped", "processing", "delivered", "cancelled"]
    estimated_delivery: str | None = None

model = init_chat_model("openai:gpt-5.5")
structured_model = model.with_structured_output(OrderStatus)

result: OrderStatus = structured_model.invoke(
    "What's the status of order ORD-1002?"
)
print(result.status)          # e.g. "shipped"
print(result.estimated_delivery)  # e.g. "2026-07-20"
What it does

The model receives the Pydantic schema as a tool-call definition and is instructed to populate it instead of generating free text. When supported by the provider, the returned object is a parsed result matching the requested shape. Provider capability and error behavior vary; consult the provider's documentation.

Official: docs.langchain.com/oss/python/langchain/structured-output · reference.langchain.com (with_structured_output)

Method 2: response_format (agent level)

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[my_tool],
    system_prompt="You are a classification assistant.",
    response_format=OrderStatus,   # <-- agent-level structured output
)

response_format is configured on the agent harness (not the model directly). The harness wraps the model's output to enforce the schema at the agent level. Use with_structured_output when working with a model directly; use response_format when building an agent.

Official: docs.langchain.com/oss/python/langchain/structured-output

Provider Capability Caveats

Not every provider supports every parameter the same way. LangChain normalises the interface, but the underlying model's capabilities set the real limits.

CapabilityNotes
Tool callingSupport and schema syntax vary by provider. Consult the provider's documentation for capabilities and limitations.
Structured outputSupport and reliability vary by provider. Providers that support JSON-mode or tool-call-based structured output can return the requested shape; others may produce partial or unexpected results. Consult your provider's documentation.
StreamingSupport and chunk structure vary by provider. Where streaming is available, AIMessageChunk normalises the chunk shape.
temperatureRange 0–1 for some models, 0–2 for others. Very high values may produce incoherent output.
max_tokensSome models treat it as a hard limit; others as a soft target. Check the provider's docs for exact semantics.
Thinking / reasoning tokensSome providers expose reasoning or thinking tokens as separate content blocks. Behavior, naming, and support vary; consult your provider's documentation.
Always test with your provider

The init_chat_model function validates the provider prefix and loads the right package, but it cannot guarantee that the model you named supports every parameter you passed. Start with simple invoke() calls and add parameters one at a time.

Debugging Checklist

When things go wrong with models and messages:

  1. Wrong provider package? Did you pip install langchain-openai (or langchain-anthropic, langchain-ollama)?
  2. Missing API key? Set export ANTHROPIC_API_KEY="..."; the provider package reads the standard env var for that provider.
  3. Wrong message type? AIMessage.tool_calls is a list, not a single dict. Iterate it. ToolMessage.tool_call_id must match the tool call's id.
  4. Structured output parse error? The model's output didn't match the Pydantic schema. Check field types, especially Literal values and optional fields. Try a simpler schema first.
  5. Unexpected max_tokens truncation? The response may be cut off mid-sentence. Increase max_tokens or set to None for the model default.
  6. Parameter ignored? Your model may not support the parameter. Check the provider's documentation for supported options.
  7. Stream not producing output? Verify stream_mode and iterate the generator. Each chunk is an AIMessageChunk; accumulate via chunk.content.
