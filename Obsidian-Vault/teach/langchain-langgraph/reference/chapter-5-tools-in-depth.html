Tools in Depth

Chapter 5 quick reference. Tool contracts, tool-call messages, runtime injection, composition, and error paths.

The mental model

The model chooses when and how to call. Your Python tool validates and acts. The harness coordinates the loop.

1. Define a tool

from langchain.tools import tool

@tool
def lookup_order(order_id: str) -> str:
    """Look up the shipping status for one order ID."""
    return ORDERS[order_id]
SourceContract effect
Function nameDefault tool name.
Type hintsInput schema the model must fill.
DocstringDefault description used for tool selection.
args_schema=ModelExplicit Pydantic or JSON Schema input contract.

Inspect tool.name, tool.description, and tool.args_schema.model_json_schema().

2. The tool-call loop

model_with_tools = model.bind_tools([lookup_order])
messages = [HumanMessage("Where is ORD-1042?")]

ai_msg = model_with_tools.invoke(messages)
messages.append(ai_msg)

for tool_call in ai_msg.tool_calls:
    messages.append(lookup_order.invoke(tool_call))

final = model_with_tools.invoke(messages)
MessageMeaning
AIMessageModel output; tool_calls contains name, args, and id.
ToolMessageExecuted result; tool_call_id matches the request ID.
Final AIMessageModel uses tool results to answer or call again.

3. Compose tools in an agent

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[lookup_order, get_shipping_eta],
    system_prompt="Use tools for order facts. Never invent a status.",
)
result = agent.invoke({"messages": [{"role": "user", "content": question}]})

The tools=[...] list is the composition boundary. The model sees every tool schema and decides which one fits. Capability varies by model.

4. Inject trusted runtime context

from dataclasses import dataclass
from langchain.tools import ToolRuntime, tool

@dataclass
class UserContext:
    user_id: str

@tool
def get_account_tier(runtime: ToolRuntime[UserContext]) -> str:
    """Return the current user's account tier."""
    return USER_TIERS.get(runtime.context.user_id, "unknown")

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[get_account_tier],
    context_schema=UserContext,
)
agent.invoke(input, context=UserContext(user_id="user_123"))
Injected fieldUse
runtime.stateShort-term conversation state.
runtime.contextImmutable per-run identity or session data.
runtime.storeLong-term cross-conversation data.
runtime.stream_writerCustom progress updates during execution.
runtime.tool_call_idCurrent call ID when returning a state update.

Reserved: runtime and config are not ordinary tool arguments. The injected runtime parameter stays out of the model-visible schema.

5. Return errors through the loop

from langchain.agents.middleware import wrap_tool_call
from langchain.messages import ToolMessage
from langchain.tools.tool_node import ToolCallRequest

@wrap_tool_call
def handle_tool_errors(request, handler) -> ToolMessage:
    try:
        return handler(request)
    except Exception:
        return ToolMessage(
            content="Check the input and try again.",
            tool_call_id=request.tool_call["id"],
        )

agent = create_agent(
    model="openai:gpt-5.5",
    tools=tools,
    middleware=[handle_tool_errors],
)

Use ToolRetryMiddleware for retry policy. An error message and a retry are different decisions.

6. Checklist

  • Every model-facing argument has a useful type hint.
  • Every tool has a concise, accurate docstring.
  • Tool results return as ToolMessage objects with matching call IDs.
  • Trusted identity and session data arrive through ToolRuntime, not model arguments.
  • Tools validate important actions in Python; prompts are not access control.
  • Provider/model tool-calling support is tested before production use.
