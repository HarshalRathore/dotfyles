State Machine Automaton

The finite-state machine that drives every create_agent agent under the hood. Three nodes, two conditional transitions, one growing messages[] state. Once you internalize this diagram, you can read any LangGraph trace.

The Automaton

Nodes

model — The LLM inference node. Receives the full message history, picks tool schemas from the agent definition, generates the next AIMessage. This is where the HTTP request to the provider happens.

tools — Executes each tool call from the model's output. LangGraph runs the registered Python function with the arguments the model chose, wraps the return value in a ToolMessage, and appends it to state.

__end__ — Terminal state. Once reached, no more nodes execute. The full messages[] list becomes the return value of agent.invoke() or the final stream() chunk.

How the Edges Decide

The only conditional branching in the entire automaton happens between model and __end__. LangGraph inspects the model's latest AIMessage.tool_calls field. The decision is binary:

The Finish Condition

tool_calls is a list[dict] on every AIMessage. Empty list [] means the model answered directly — go to __end__. Non-empty list means the model wants tool results first — go to tools.

① model → tools — Condition: len(aimsg.tool_calls) > 0. LangGraph routes each tool call to its registered function. The provider's HTTP response included finish_reason: "tool_calls".
② tools → model — Unconditional. After every tool execution, the graph routes back to the model. No decision is made here — the model must decide again whether it has enough information.
③ model → __end__ — Condition: len(aimsg.tool_calls) == 0. The model produced a final text answer. The provider's HTTP response included finish_reason: "stop".

Stream Chunks At Each Transition

When you use stream_mode="updates", the automaton yields one chunk per executed node. Each chunk is a dictionary with the node name as key and the delta to state as value:

Transition Yields Meaning
model node runs {"model": {"messages": [AIMessage(content="", tool_calls=[...])]}} Model decided to call tools. tool_calls non-empty.
tools node runs {"tools": {"messages": [ToolMessage(content="...", name="lookup_shipping_status")]}} Python function executed. Result wrapped as ToolMessage.
model node runs {"model": {"messages": [AIMessage(content="Your order...", tool_calls=[])]}} Model answered directly. tool_calls empty → will route to __end__.
__end__ {"__end__": None} Terminal event. No more chunks after this. 
MODEL calling tool: lookup_shipping_status({'order_id': 'ORD-1002'})
TOOL  result: Processing. Estimated ship date: tomorrow
MODEL final: Your order ORD-1002 is being processed...
END

The trace above is what each stream_mode="updates" chunk looks like after your loop body processes it. One event per node execution. The __end__ chunk signals no more state changes will arrive.

State Accumulation

The automaton's state is a flat grow-only list: messages[]. Each node appends to it — nothing is ever removed. The initial invoke call inserts the user message; each model call appends an AIMessage; each tool execution appends a ToolMessage.

[USER] {"role": "user", "content": "Where is ORD-1002?"} [AI] {"role": "assistant", "content": "", "tool_calls": [{"name": "lookup_shipping_status", "args": {"order_id": "ORD-1002"}}]} [TOOL] {"role": "tool", "content": "Processing. Estimated ship date: tomorrow", "name": "lookup_shipping_status"} [AI] {"role": "assistant", "content": "Your order ORD-1002 is being processed and is estimated to ship tomorrow.", "tool_calls": []}

Each message carries a role that tells you which part of the system produced it. The model sees the entire list on every invocation — that accumulated history is what lets it pick up where it left off.

One Complete Round Trip

A single model-to-model iteration involves:

1 Iteration = 1 HTTP Round Trip

1. LangGraph serializes state.messages[] into the provider's API format.

2. It sends POST /v1/chat/completions with messages plus tool schemas in the request body.

3. The provider streams or returns a response containing the model's next message (tokens, tool calls, finish reason).

4. LangGraph deserializes the response into an AIMessage and appends it to state.

5. If tool_calls non-empty → tools node executes → ToolMessages appended → back to step 1. If empty → __end__.
