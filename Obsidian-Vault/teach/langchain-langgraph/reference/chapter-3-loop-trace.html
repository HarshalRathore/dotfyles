Loop Tracing Quick Reference

Chapter 3 essentials: messages, stream modes, finish condition, and trace reading. Keep this open as you work through the course.

The Finish Condition

The loop's single rule

The agent loop ends when the latest AIMessage has an empty tool_calls list. Non-empty tool_calls means continue. Empty tool_calls means route to __end__. That is the entire stop/go decision.

Model → tool_calls? → [yes] Execute tools ← loop [no] END

Message Types

TypeSourceKey FieldsRole
HumanMessage User input content Carries the user's question or instruction.
AIMessage Model output content, tool_calls Model's response. tool_calls is a list of dicts: name, args, id.
ToolMessage Tool execution content, tool_call_id Result of a tool call. tool_call_id links it to the AIMessage that requested it.
SystemMessage Session start content System prompt injected at the start of every conversation.

Stream API

Parameters

ParameterValuesPurpose
stream_mode"updates" (recommended), "values"Controls what each chunk contains: state changes or full state.
version"v2"Streaming API version. V2 is the current standard.

stream_mode='updates' vs 'values'

ModeYieldsWhen to use
'updates'State changes per node onlyStandard tracing, debugging, logging
'values'Full accumulated state after each nodeOnly when you need complete state, including private channels

Stream loop pattern

for chunk in agent.stream(
    {"messages": [{"role": "user", "content": "..."}]},
    stream_mode="updates",
    version="v2",
):
    for node_name, data in chunk.items():
        if node_name == "model":
            msg = data["messages"][-1]
            if msg.tool_calls:
                print(f"[MODEL] calling tool: {msg.tool_calls[0]['name']}")
            else:
                print(f"[MODEL] final: {msg.content}")
        elif node_name == "tools":
            print(f"[TOOL] result: {data['messages'][-1].content}")

Trace Structure

A basic agent trace follows this pattern. Each line corresponds to one graph node execution:

MODEL calling tool: lookup_shipping_status({'order_id':'ORD-1002'})
TOOL result: Processing. Estimated ship date: tomorrow.
MODEL final: Your order is being processed...
END
Trace rhythm

MODEL (tool call) always leads to TOOL (result). MODEL (final answer) leads to END. Multiple tool calls produce repeated MODEL → TOOL pairs before the final MODEL → END.

How It Works: Model vs Framework

ComponentWhat it does
ModelEmits structured JSON describing a tool call (name, args, id). Never calls functions. Never runs Python code.
FrameworkParses the model's JSON output, matches tool name to registered Python function, calls it with parsed args, wraps result in ToolMessage, appends to history.
ResultThe model suggests. The framework executes. The loop feeds back.

Thinking / Reasoning Tokens

  • Provider-dependent — OpenAI o-series, Claude Opus may expose reasoning; smaller models generally do not.
  • NOT the same as trace events — reasoning is model-internal; trace events are graph node executions.
  • May require explicit model settings — not guaranteed to appear.
  • Never build logic on reasoning output — it is not a stable API.

Ways the Loop Can End

Exit typeTrigger
Normal finishLatest AIMessage has empty tool_calls. Graph routes to __end__.
Middleware terminationGuardrail sends graph directly to __end__.
Structured outputOutput schema node completes, ending execution.
Error / exceptionTool raises an unhandled Python exception.
Recursion limitGraph exceeds default 25 iterations.
No more nodesGraph topology has no outgoing edge.

Key Terms

TermDefinition
tool_callsList on AIMessage containing dicts with name, args, id. Empty = loop ends. Non-empty = loop continues.
tool_call_idField on ToolMessage that links the result back to the specific AIMessage tool_call that produced it.
StreamMethod that yields per-node updates as the graph executes, instead of blocking for the full result.
stream_modeParameter controlling whether stream yields state changes (updates) or full state (values).
__end__Special graph node that terminates execution. The destination when no more tools need calling.
Thinking tokensModel-internal reasoning output. Provider-dependent. Not part of the stable agent loop API.
