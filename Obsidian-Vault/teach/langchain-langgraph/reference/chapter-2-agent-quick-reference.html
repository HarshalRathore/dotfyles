LangChain Agent Quick Reference

Chapter 2 essentials: the mental model, the API skeleton, tool rules, and the hidden loop. Keep this open as you work through the course.

The Mental Model

Model + Tools + Loop = Agent

A LangChain agent is model + tools + loop. The model reasons. The tools act. The loop connects them, repeating until the model produces a final answer instead of a tool call.

Installation

python3 -m venv .venv
source .venv/bin/activate
pip install -U langchain
pip install -U langchain-openai  # or langchain-anthropic, langchain-ollama
export OPENAI_API_KEY="sk-..."    # your provider key

LangChain is provider-agnostic. The core package handles the framework. Provider packages handle model-specific APIs.

API Skeleton

from langchain.agents import create_agent
from langchain.tools import tool

@tool
def my_tool(param: str) -> str:
    """Description the model reads to decide when to call this."""
    # Your logic here (safe: dict lookup, calculation, etc.)
    return f"Result: {param}"

agent = create_agent(
    model="openai:gpt-4o",        # provider:model_id
    tools=[my_tool],               # list of @tool functions
    system_prompt="You are a...",  # instructions for the model
)

result = agent.invoke({
    "messages": [{"role": "user", "content": "Your question here"}]
})
print(result["messages"][-1].content_blocks)

Tool Rules

Safe tool principles
  • No eval(), exec(), or arbitrary code execution
  • No shell commands, filesystem writes, or network calls (yet)
  • Use dict lookups, calculations, or fixed data
  • Write clear docstrings — the model reads them to decide when to call
  • Use type hints — LangChain infers the input schema from them
How the model sees your tool

For each @tool function, LangChain builds a JSON schema containing the function name, docstring (becomes the tool description), and parameter types (become the input schema). The model receives this schema alongside the system prompt and user message.

The Hidden Loop (Numbered)

Everything inside agent.invoke():

1 Message in. User message + system prompt + tool schemas sent to model.
2 Model decides. Model reads everything and emits a tool call (name + args) or a final answer.
3 Harness intercepts. The loop sees the tool call, extracts name + parsed arguments.
4 Tool runs. Your Python function executes with the parsed arguments.
5 Result feeds back. Return value wrapped as ToolMessage, appended to conversation.
6 Model decides again. With result in context, model chooses: another tool call or a final answer.
7 Stop. If model outputs a text answer (not a tool call), loop ends. Full message list returned.

Key Terms

TermDefinition
Model identifierprovider:model_id string, e.g. "openai:gpt-4o".
ProviderCompany serving the model; each has its own pip package.
System promptInstructions at the start of every conversation. Sets behavior and constraints.
@toolDecorator that turns a function into a tool schema for the model.
create_agentFactory function that wires model + tools + prompt into an agent harness.
invoke()Method that runs the full agent loop with a message input.
Tool callModel's structured request: "call function X with arguments Y".
ToolMessageMessage type holding the result of a tool execution.

What This Doesn't Do Yet

  • No memory — each invoke starts fresh. (Chapter 9)
  • No custom branching — no conditional logic between steps. (Chapters 6-8)
  • No durable workflow — crash mid-loop loses everything. (Chapter 9)
  • No middleware — no guardrails, retries, or logging. (Chapter 5)
