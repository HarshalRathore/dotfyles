Orientation: Agents, Frameworks, and the Mailroom

The big picture before the code. What LangChain and LangGraph are, how they fit together, and the one mental model that will carry you through this entire course.

You know Python. You have probably talked to ChatGPT or Claude. You might have written a script that calls an LLM API. But you have never used LangChain or LangGraph. That changes now.

By the end of this lesson you will be able to answer three questions:

  • What is an agent, exactly?
  • What does LangChain do and what does LangGraph do?
  • Where do I look things up when I get stuck?

The Mental Model: Agent = Model + Tools + Loop

Every agent in this course reduces to exactly three parts:

Model
+
Tools
+
Loop

Agent = reasoning engine + capabilities + repetition

Model

The LLM that decides what to do next. Given a message, it either answers directly or decides a tool needs to be called.

Tools

Functions the model can invoke: look up a database, call an API, run a calculation. Each tool has a name, description, and input schema.

Loop

The repetition that lets the agent work through multi-step tasks. The pattern: receive input, decide action, execute, observe result, decide again, repeat until done.

That is it. Everything else (state management, persistence, middleware, streaming) is infrastructure around these three parts. If you ever get lost in later chapters, come back to this triangle. It anchors everything.

Key insight

The model does not actually call functions. It outputs a structured request like tool_call(name="get_weather", args={city: "Paris"}). The loop intercepts this request, runs the function, and feeds the result back as a new message. The model never touches external code directly. It just emits structured tool calls, and the loop makes them real.

LangChain vs LangGraph: The Stack

LangChain and LangGraph are not alternatives. LangChain is built on top of LangGraph. Think of it as two layers of control:

LangChain
High-level framework. create_agent, tool abstractions, middleware.
LangGraph
Low-level runtime. State graphs, durable execution, persistence.
Model Provider
OpenAI, Anthropic, Ollama, or any LLM.
Python 3.10+
Your code, virtual environment, pip packages.
Use LangChain when
you want a standard agent fast. One model, a few tools, a system prompt, done.
Use LangGraph when
you need custom state machines, long-running agents, persistence, or human-in-the-loop.

The key quote from the official docs: "While LangChain is built on top of LangGraph, you don't need to know LangGraph to use LangChain."

This means Chapter 2 through Chapter 5 will use only LangChain. You will not see a graph until Chapter 6. And that is deliberate. LangChain's create_agent is the fastest way to get a working agent on screen, and the concepts you learn there (models, tools, messages) transfer directly into LangGraph later.

Watch out

The old domains python.langchain.com and langchain-ai.github.io/langgraph/ now redirect to docs.langchain.com. Always use the new URL. Tutorials on the old domains may return 404.

The Mailroom Analogy

Imagine the mailroom at a large company. Every day, letters arrive and must be routed to the right department.

Mailroom manager
Model Reads each letter, decides where it goes: billing, shipping, HR, or handles it directly.
Departments
Tools Each department has a specific function. Billing processes payments. Shipping dispatches packages. HR handles employee inquiries.
Conveyor belt
Loop The physical system that moves letters from inbox to manager to department and back. Reliable, repeatable, observable.
Procedures manual
LangChain The standard procedures: "when a billing letter arrives, do X." High-level, reusable, easy to use without knowing the conveyor design.
Conveyor infrastructure
LangGraph The belts, sensors, and control system. You only touch this when you need custom routing, failover, or multi-floor workflows.
Logbook
LangSmith A record of every letter, routing decision, and delivery. Useful for debugging, but not part of the core system.

The mailroom analogy will reappear throughout this course. When a concept feels abstract, ask: "what does this map to in the mailroom?"

Quick Glossary

Ten terms to get you started. The full reference glossary has every definition with official source links.

TermPlain English
AgentA model that calls tools in a loop until a task is complete. The whole point of this course.
ModelThe LLM reasoning engine. Accepts messages, returns messages. GPT, Claude, Llama.
ToolA function the model can invoke. Created with @tool. Has a name, description, and input schema.
LoopThe repetition: model decides, tool runs, result feeds back, model decides again. Repeats until the task is done.
MessageThe I/O unit. HumanMessage, AIMessage, SystemMessage, ToolMessage. Every interaction is messages.
StateIn LangGraph: the current information and work-in-progress at a given moment. Checkpoints are saved snapshots of that state. State flows through every node in the graph as the source of truth.
NodeA function in a graph that receives state and returns an update. "Nodes do the work."
EdgeA function that routes between nodes based on state. "Edges tell what to do next."
CompileThe step that validates a graph and makes it runnable. graph.compile().
HarnessEverything around the model loop: prompt, tools, middleware. create_agent is the standard harness.

5-Minute Exercise: Spot the Parts

Look at this complete LangChain agent. Without running it, see if you can identify the model, tools, and loop:

from langchain.agents import create_agent

def get_weather(city: str) -> str:
    """Get weather for a given city."""
    return f"Sunny in {city}!"

def calculate(expression: str) -> str:
    """Evaluate a math expression safely."""
    import ast, operator
    MAX_INPUT_LEN = 200
    MAX_DEPTH = 10
    if len(expression) > MAX_INPUT_LEN:
        return "Error: expression too long"
    ops = {ast.Add: operator.add, ast.Sub: operator.sub,
           ast.Mult: operator.mul, ast.Div: operator.truediv,
           ast.USub: operator.neg}
    def _eval(node, _depth=0):
        if _depth > MAX_DEPTH:
            raise ValueError("expression too deep")
        if isinstance(node, ast.Constant) and isinstance(node.value, (int, float)):
            return node.value
        if isinstance(node, ast.UnaryOp) and type(node.op) in ops:
            return ops[type(node.op)](_eval(node.operand, _depth+1))
        if isinstance(node, ast.BinOp) and type(node.op) in ops:
            return ops[type(node.op)](_eval(node.left, _depth+1), _eval(node.right, _depth+1))
        raise ValueError("unsafe expression")
    return str(_eval(ast.parse(expression, mode="eval").body))

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[get_weather, calculate],
    system_prompt="You are a helpful assistant.",
)

result = agent.invoke(
    {"messages": [{"role": "user",
      "content": "What's the weather in Paris and 2+2?"}]}
)
print(result["messages"][-1].content_blocks)
Your turn (60 seconds each)
1 Where is the model specified? What does openai:gpt-5.5 mean?
2 How many tools does this agent have? What do they do?
3 Where is the loop? (Hint: you do not see it directly. It is inside create_agent.)
4 The user asks about two things (weather in Paris, 2+2). How many tool calls do you expect the agent to make?
Reveal answers

1. model="openai:gpt-5.5". This is shorthand for "use the OpenAI provider with the gpt-5.5 model." LangChain maps this to a model class from the langchain-openai package.

2. Two tools: get_weather (takes a city name, returns weather) and calculate (evaluates a math expression). The docstrings are critical. They are sent to the model so it knows when to call each tool.

3. The loop is inside create_agent. Behind the scenes it runs: model decides, if tool call then execute, feed result back, model decides again, repeat until the model answers directly.

4. Likely two calls (one per tool), then a final answer. The agent might make them in parallel if the model supports parallel tool calling. The loop ends when the model produces a final text response instead of a tool call.
