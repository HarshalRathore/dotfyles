## The Article

Deep dive: [[references/how-a-gpu-actually-works|How a GPU Actually Works]].

The article builds an intuition for GPU performance from one asymmetry — arithmetic is cheap, moving data is expensive — and derives everything else from it. ^[extracted]

Headline results:
- **Memory bandwidth vs compute asymmetry:** arithmetic capability has grown several times faster than bandwidth across recent accelerator generations, so the imbalance worsens every generation and raw TFLOPS predicts less and less. ^[extracted]
- **Decode is memory-bound:** a 70B fp16 model must read ~140 GB of weights per token; at ~3.3 TB/s that is ~42 ms/token — a ~24 tok/s floor that no software cleverness moves. ^[extracted]
- **Break-even ratio:** H100's 989 TFLOPS (BF16) ÷ 3.35 TB/s ≈ 295 ops/byte (~300); below it a workload is memory-bound, above it compute-bound. H200's 4.8 TB/s drops the threshold to ~206 ops/byte, which is why bandwidth upgrades speed up inference without adding arithmetic. ^[extracted]
- **Every optimization is one of two moves:** increase work per fetch (batching, tiling) or decrease bytes fetched (fusion, quantization, memory layout) — e.g. 8-bit quantization halves bytes and roughly doubles the token ceiling to ~48 tok/s. ^[extracted]
- **Prefill is the opposite case:** processing many tokens at once makes prefill usually compute-bound, so one model has two phases with opposite bottlenecks. ^[extracted]
