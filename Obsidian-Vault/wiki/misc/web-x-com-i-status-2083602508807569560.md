# Graph Engineering Course: The X Post, Linked Architecture, and Captured Lab

> **Source:** [Codila's X post](https://x.com/i/status/2083602508807569560), captured through a text mirror. The post advertises a free Google two-hour course and links to a longer architecture article. ^[extracted]

## What the Post Claims

The post frames the course as a progression from one prompt to many agents, loops, and graphs. Its chapter markers highlight building an agent, loop engineering, graph engineering, self-throttling agents, and a full multi-agent graph. ^[extracted]

The linked article calls graph engineering the successor to loop engineering: a loop improves one task by trying, checking, and adjusting; a graph connects multiple work nodes with dependency edges so independent work can fan out and verification can gate downstream work. ^[extracted]

## Linked Architecture Article

The article's practical method is:

1. Treat each unit of work as a node and each real data dependency as an edge.
2. Remove false edges created by writing steps as “and then” when the later step does not consume the earlier result.
3. Fan out independent work, then verify findings with a fresh context rather than asking an executor to approve its own output.
4. Give parallel workers isolated workspaces and define how conflicts merge before scaling.
5. Anchor the graph in evidence such as tests that actually ran, not mutually reinforcing agent claims. ^[extracted]

The article also gives a scale example of up to 1,000 agents per workflow run with 16 concurrent workers, and a Bun migration example reported at roughly 535,000 lines of Zig translated into more than one million lines of Rust in 11 days at about $165,000 of usage. These are article-reported figures, not independently verified benchmarks. ^[ambiguous]

It explicitly says a graph is the wrong tool for a small isolated task, a task requiring tight step-by-step oversight, exploratory work without a known shape, or work whose steps genuinely depend on one another. ^[extracted]
