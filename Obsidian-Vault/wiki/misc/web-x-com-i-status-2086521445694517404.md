## The Article

The post links a long-form companion page on the Command Code docs site — **"The Read Tool"** (Harness Engineering section): https://commandcode.ai/docs/harness-engineering/read-tool

Deep dive: [[references/command-code-read-tool-harness-engineering|Command Code's Read Tool: Harness-Engineering Deep Dive]].

Core claims:
- `read_file` is "a compiler that turns your filesystem into the model's context" — every decision inside it is a token-budget decision multiplied by ~50M uses/month. ^[extracted]
- Napkin math: 500 junk tokens × 50M reads/month = 25B junk tokens/month, paid again on every turn they stay in context. ^[extracted]
- Claude Code's read tool succeeds by spending more (no window, no byte ceiling, no per-line clamp); Command Code had to succeed by spending less because open models can't recover from sloppy reads. ^[extracted]
- Benchmark of 10 harnesses (Command Code, Claude Code, OpenCode, Cline, Kilo, Codex, Grok Build, Hermes Agent, Pi, OpenClaw): the "top of the table" (line window + a second ceiling) is solved by 8/10; the "bottom of the table" (deferred chunk cut, unicode name retry, device blocklist, EOF note, coord scale note, did-you-mean, partial-view ledger) is empty almost everywhere — 1-3/10 at best. ^[extracted]
- "Constraint is a feature" — running open models forces harness engineering because a wasted turn shows in the eval score the same day. ^[extracted]
